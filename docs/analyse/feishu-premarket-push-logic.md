# 系统实际的飞书盘前推送逻辑

本文说明 `ah_recommendation_system` 当前代码中真正执行的盘前推送流程，不是 `market-composite-advisor` 分析模板。

## 1. 触发入口

Windows 计划任务由 `tools/install_stock_recommend_tasks.ps1` 注册：

- 工作日 08:30：
  `python -m scheduler.daily_job --mode pre_market --push`
- 工作目录：`ah_recommendation_system/backend`
- 推送开关：命令行 `--push`
- 飞书地址：环境变量 `AH_FEISHU_WEBHOOK`，或 `C:\Users\Administrator\Downloads\feishu_key.txt`
- 签名密钥：可选环境变量 `AH_FEISHU_SECRET`

实际入口是 `stock_recommend.run.run_pipeline()`，而不是分析 skill。

## 2. 总体流程

```text
采集行情 / 资金 / 新闻
        ↓
当前快照动态扫描，生成候选来源标签
        ↓
确定性因子计算与排序（最多约30只）
        ↓
实时模式下做热点映射和“消息面”LLM复核
        ↓
再次确定性排序
        ↓
硬门槛筛选 + 行业去集中，形成正式个股推荐
        ↓
实时模式下单独筛选 ETF（最多3只）
        ↓
保存 JSON/Markdown，并组装飞书 interactive card
```

## 3. 采集哪些数据

### 基本面与行情

首选同花顺 Financial-API（配置 Key 时），否则尝试 AKShare 的 A 股全市场快照。主要字段包括：代码、名称、价格、涨跌幅、PE、PB、市值、成交额、换手率和 60 日涨跌幅。

实时源不可用时按以下顺序降级：

`hithink_financial_api → tencent / sina / baostock / akshare → 最近一次有效快照`

如果只能使用重点行业或旧快照，报告会标记为 `degraded` / `failed`，不会把旧数据伪装成当日实时推荐。

### 资金面

- 个股主力净流入；
- 沪深港通汇总（北向背景）；
- Financial-API 可用时补充龙虎榜机构和游资净买入。

龙虎榜资金本身只是候选来源，不能单独成为正式推荐依据。

### 事件面

- 个股新闻/公告；
- 宏观 RSS 新闻；
- 实时模式下先做热点主题与行业映射，再对候选股已有新闻进行 LLM 复核。

LLM 只复核已有事件，不联网编造新闻，也不替代趋势、量价和风险硬门槛。

## 4. 候选池如何动态生成

`dynamic_scanner.scan_snapshot()` 每次运行都重新扫描当前快照，打上以下标签：

- **流动性龙头**：成交额排名前 300 且成交额至少 1 亿元；
- **市场领涨**：当日涨幅至少 3%；
- **放量**：量比至少 1.5 且成交额至少 1 亿元；
- **阶段新高**：价格接近或超过 20 日高点（不低于高点的 99.5%）；
- **相对强度**：60 日涨幅至少 10%；
- **抗跌/韧性**：当日不跌且 60 日动量为正；
- **资金活动**：机构或活跃营业部净买入；
- **重点行业**：仅作为候选来源和行业归属标签，不直接加分。

候选按标签数量、成交额、60 日动量排序，通常取前 30 只进入评分阶段。

## 5. 综合评分

当前有效的默认权重为：

| 因子 | 权重 | 主要含义 |
| --- | ---: | --- |
| 趋势 `trend` | 25% | 60 日动量、站上 MA20/MA60 等 |
| 量价 `price_volume` | 20% | 成交额和量比，确认价格是否有资金支持 |
| 估值质量 `value_quality` | 15% | PE 越合理，分数越高 |
| 资金 `capital` | 15% | 主力净流入强弱 |
| 相对强度 `relative_strength` | 15% | 当日表现与 60 日表现的组合 |
| 消息催化 `event` | 10% | 新闻/公告是否与股票匹配、是否偏正面 |

总分是各因子加权和，再叠加风险扣分：20 日波动率过高或最大回撤过大时，最多扣约 0.08。分数范围按 0—1 处理，正式筛选默认要求综合分至少 `0.55`。

消息分规则大致为：

- 普通正面新闻：`0.8`；
- 普通负面新闻（如减持、诉讼、亏损）：`0.15`；
- 重大负面新闻（立案、重大处罚、财务造假、退市风险等）：`0`，并触发 `p0` 否决。

实时模式下，消息 LLM 分数与规则分数按 **70% 规则 + 30% LLM** 混合；其他因子和硬风险门槛不变。

### 当前权重文件的实际情况

`backend/data/stock_recommend/factor_weights.json` 目前保存的是旧版 `fundamental/capital/event` 三因子格式，缺少 `factor_version=evidence-v1` 和六因子完整集合。因此 `load_factor_weights()` 会拒绝该文件并回退到上表的默认六因子权重。也就是说，当前运行实际使用的是默认权重，而不是该文件中的 0.4/0.35/0.25。

## 6. 正式推荐的硬门槛

`rule_selector.select_by_rules()` 会跳过观察标的，并要求：

1. 至少 3 个有效证据维度；
2. 证据中必须包含趋势或量价；
3. 质量等级为 A 或 B；
4. 综合分不低于 `0.55`；
5. 不能有重大负面、陈旧数据或历史覆盖不足等否决项；
6. 同一重点行业已有更高排名标的时，后者因集中度被排除。

候选构建阶段还会排除或降级：

- ST、退市、暂停、B 股名称；
- 若数据存在，市值低于 50 亿元；
- 若数据存在，PE 不在 `0—80` 的有效范围；
- 成交额缺失或低于 1 亿元；
- 缺少至少 60 个交易日历史；
- 价格不在 3—300 元；
- 当日涨跌幅不在约 `-4%—+8.5%`；
- 仅有龙虎榜资金、但没有行业/价格确认的标的。

因此，正式推荐可以是 0 只。虽然旧 README 写过“0—3 只”，但当前 `run_pipeline()` 默认 `top_n_pick=5`，实际最多可选 5 只；最终数量仍受硬门槛和行业去集中约束。

## 7. 推荐内容如何生成

每只正式推荐的动作当前固定写为 `WATCH`，并不是无条件 `BUY`。系统会输出：

- 买入区间：支撑位到当前价格；
- 止损：支撑位减去约 `1.25 × ATR`；
- 目标：阻力位；
- 持有周期：默认 5—20 个交易日；
- 触发条件：板块不转弱、价格站稳前一日收盘、成交额不低于 20 日均值；
- 失效条件：收盘跌破风险边界，或板块与个股相对强度同时转弱；
- 理由、证据、因子分数和风险提示。

未达到正式门槛的候选不会消失，而是进入“观察池”，并记录拒绝原因，例如证据不足、成交额不足、历史不足或风险过高。

实时模式还会独立生成 ETF 质量评分，最多选 3 只，默认最低综合分为 60；若 ETF 数据阶段失败，报告构建器会使用宽基、证券、创业板等默认观察 ETF，但这不等于实时 ETF 已确认。

## 8. 飞书卡片展示什么

`feishu_pusher.build_card()` 将报告转换为 interactive card，内容顺序是：

1. 数据降级/覆盖范围告警；
2. **盘前总结**；
3. **大盘看法**；
4. 消息热点及行业映射；
5. 个股逐只展示：动作、信心度、买入区间、止损、目标、持有期、理由、六因子分数、AI 消息复核和风险；
6. ETF 观察（最多 3 只）；
7. 整体证伪信号。

没有通过门槛的个股时，卡片显示“暂无推荐”或“有限数据源下暂无个股通过确认条件”。

推送使用飞书机器人 Webhook：成功条件为 HTTP 200 且业务码为空/0；失败最多重试 3 次，退避时间约为 1、2 秒。未配置 Webhook 时会跳过推送并返回 `AH_FEISHU_WEBHOOK not set`。

## 9. 一句话概括

系统盘前飞书推送的真实逻辑是：**采集当日可得的 A 股行情、资金和新闻 → 动态生成候选 → 用趋势、量价、估值、资金、相对强度和消息六因子打分 → 通过证据、数据质量、风险和行业集中度硬门槛 → 输出 WATCH 型观察建议 → 通过 Webhook 推送卡片。**

它是规则引擎主导的短线观察系统，LLM 只参与实时事件/消息维度复核，不是由大模型直接自由选股。
