## 优先问题与代码证据

### P0：旧版估值分数使用固定参数

`ah_recommendation_system/backend/strategies/multi_factor.py:141-148` 对个股统一设置 PE=12、PB=1.5、股息率=3.0，再用于评分。即使价格来自实时源，也不构成真实的个股估值比较。

建议：在修复前标为演示/不参与投资判断；随后接入真实基本面数据，并明确缺失值处理，不能用统一常数伪装实际估值。

### P0：旧版 ML 置信度不是胜率，训练评估不适合直接验证交易有效性

`backend/strategies/ml_predictor.py:156-162`（路径前缀同上）先对全部样本拟合 StandardScaler，再随机划分训练/测试集；不具备严格时间顺序隔离。
`ml_predictor.py:250-277` 将预测幅度换算为 confidence；无模型时用近期溢价趋势并给固定 confidence=0.5 或 0.3。不能把这些数读成获利概率。

建议：清晰区分训练模型预测与规则回退；置信度改用准确含义名称，采用按时间切分、滚动样本外验证及成本后基准比较后再谈有效性。

### P0：来源、报告时点与有效期未统一展示

`backend/main.py:91-99` 默认 mock。`frontend/index.html:253-258` 顶部演示/模拟标识是静态文案。
`backend/api/report_routes.py:21-30` 直接返回最新存储报告；`backend/reporting/report_store.py:20-22` 按修改时间选择，不对报告内容新鲜度作统一拦截。
`frontend/index.html:1905-1912` 新版主要显示 as_of、理由和部分降级提示，没有完整展示生成时间、昨收口径、质量门槛和有效期。

建议：对每个模块分别显示真实/模拟、行情截至时间、生成时间、覆盖范围、降级原因和有效期；旧报告可查看但需明显提示，不能仅靠页面整体的模式标识。

### P1：ETF 上游异常回退不完整

`backend/api/etf_sector_routes.py:150-183`：自动选 ETF 在历史趋势回退判断之前执行，异常被转换为 HTTP 500。
`backend/etf_sector/etf_universe_selector.py:1212-1219`：直接调用行情和板块上游。
`backend/tests/test_etf_trend_upgrade.py:281-291`：测试替换了趋势生成及存储加载，却漏掉自动选 ETF 的真实网络请求。

建议：把采集异常也纳入回退分支；回退时明确陈旧数据与时间，不得假装实时成功；测试必须隔离自动选池依赖。

### P1：模拟运行不等于所有模块离线

`backend/run_daily_job.py:219-223` 只启用 price_fetcher 的 mock；`run_daily_job.py:189-194` 仍调用 ETF/板块模块；`backend/etf_sector/etf_sector_report.py:123-128` 直接请求新浪和同花顺。
`backend/tests/test_daily_report_backtest_integration.py:11-13` 注释声称离线，但实际会触达这些网络依赖。

建议：明确演示模式的作用范围，提供真正可离线重放的测试数据与测试入口。

### P1：缺失收益可能被显示为 0.00%

`frontend/index.html:1900` 使用 Number(v) 格式化收益；Node 实跑确认 null 与空字符串均显示 0.00%。应显示“待验证/缺失”，不能误读为收益恰好为零。

### P1：统计命名与有效性证据需要分离

`backend/api/stock_recommend_routes.py:48-64` 中 verified_reports 使用 len(rows)，并对有值的报告命中率简单平均。它不是已完成样本数，也不是按股票样本加权的胜率。

建议：分别报告已到期、有效、缺失和未到期样本，统一观察窗口，提供基准超额、成本后收益和回撤。现有接口 T+5 命中率为空，不能证明系统选股有效或无效。

## 并行审计补充（主审已再次核对源码）

以下为源码确认的问题，未实施修复，亦未据此推算实际收益影响。

### P0：配对回测的仓位与收益时序错误

`backend/backtest/pair_trading_backtest.py:92-141` 先按当日信号开平仓，再使用更新后的仓位计算昨日到今日的收益。新仓可能获得入场前的收益，平仓日则可能漏计此前持仓应有收益。`:111-127` 又在扣入场费后记录交易起始权益，使单笔交易统计不完整反映入场费。当前配对回测不可作为可靠收益证据；需先修正成交时点和成本口径并添加最小回归测试。

### P0：新版历史完整率的分子分母使用相同筛选条件

`backend/stock_recommend/run.py:1056-1058、1070-1072` 的 history_target_count 与 history_count 都统计“已成为候选且 history_days>=60”的行。`quality_gate.py:55-62` 因而不能可靠衡量原本应取得历史的候选中究竟有多少成功；当目标数为0时还会回退到 candidate_count，因此不是所有情况都恒通过。应分别统计预定采集目标与实际成功数量。新版存在质量门不等于每一项质量门都有效。

### P1：新版 ranker 的晋级比较没有独立基线

`backend/stock_recommend/rolling_calibration.py:270-292` 使用同一模型的 evaluate(test) 同时生成 baseline_metrics 和 test_metrics；`:296-301` 却要求测试值严格高于基线。当前确定性逻辑下，该比较无法证明提升，并阻断有折数情况下的晋级。评估还跨窗口只取最高5行，回撤写为0（`:270-278`）。这说明验证实现不完整，不证明模型本身无效。

修订优先级：第一阶段除可信展示外，必须纳入配对回测时序与新版质量指标分母修复；在此之前不依赖回测收益或 quality_gate=passed 作投资决策。

## 值得保留的基础

- 新版不是无条件给满推荐：`backend/stock_recommend/quality_gate.py:18-123` 包含数据源、时效、覆盖、历史完整性、证据及估值缺失检查。
- `backend/stock_recommend/run.py:1223-1234` 在质量门槛失败时清空正式股票与 ETF；`:1245-1256` 阻止质量不合格报告的正常推荐推送。
- 已有盘前/盘后报告和验证账本读取路径，适合迭代为可审计的研究工具。
- 这些证明流程约束存在，不等同于证据内容均正确、策略具有超额收益或真实推送稳定。

## 建议的推进顺序

1. **可信展示与风险隔离**：先防止将演示、旧数据、规则分数当作实时可执行结论；旧版估值和 ML 功能优先标识或暂降级。
2. **稳定运行**：补 ETF 异常回退和离线测试；以小范围真实数据检查关键字段与时间，再验证调度。
3. **统一研究决策卡**：市场环境、主攻方向、中期逻辑、提前布局条件、观察标的、触发/否定条件与证据来源。
4. **持续验证**：冻结当时判断，按到期样本评估成本后收益、超额与回撤，再决定是否调权，不先用评分高低证明选股能力。
